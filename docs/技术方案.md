# 师范专业 AI 试讲台系统 — 技术方案

> 软件工程课程设计 · v0.2(2026-09-13)
> 配套文档:[环境配置.md](./环境配置.md)

## 1. 项目概述

面向师范类专业学生的 AI 虚拟试讲训练与考核平台,用虚拟学生 + AI 多维度评测辅助/替代真实课堂试讲,覆盖课前磨课、技能训练、教学评价、达标认证全流程。

**课程设计定位**:在有限周期内实现**可演示的核心业务闭环**;对题目中的商业级技术要求(微服务、直播、AI 音视频分析)采取「分级实现 + 延后项管理」策略——核心维度真实实现(文本规则引擎,普通话/教姿教态借百度语音识别与人体分析 API),工程量大的项(直播、微服务拆分)尽力完成,进度不足则明确标注**实现延后**并给出演进设计。

### 2.4 技术难点与实现延后清单(答辩口径)

| 技术难点 | 实现方案 | 状态 |
|---|---|---|
| 普通话标准度评测 | 百度**语音识别 API**:音频按 60s 切段循环识别 → 识别文本与试讲稿比对**字错率(CER)** + 词置信度 + 通顺度 → 规则换算为普通话维度分 | 计划实现(迭代 5);API 不可用时自动回退「自评量表 + 教师评分」 |
| 教姿教态评测(站姿/走动/手势/朝向) | 百度**人体关键点识别 API**:FFmpeg 抽帧(每 2~5s 1 帧)→ 关键点计算躯干直立度、走动幅度、手势活跃度、面向朝向;眼神用面部朝向角度近似 | 计划实现(迭代 5);同上回退 |
| 音视频直播 | 录制回放(HLS/MP4)+ SRS 开源流媒体服务推拉流,浏览器 flv.js/HLS 播放 | 尽力完成(迭代 5);工期不足则**延后**,保留文字观摩点评兜底 |
| 微服务 | 模块化单体交付核心闭环;进度允许时做**最小拆分**(evaluate-service + Gateway + Nacos,2~3 个服务,见 3.1) | 尽力完成(迭代 5);拆分蓝图论证随时可讲 |
| 大模型语义评测 | `LlmEvaluator` 扩展点,配置开关切换 | 预留接口,按需接入 |

答辩口径:**能真实实现的做扎实**(文本规则引擎 + 百度 API 音视频评测),**工期敏感的明确延后**(直播、微服务),每一处取舍都有理由、有兜底、有演进路径。

## 3. 总体架构

### 3.1 架构选型:模块化单体 + 微服务演进蓝图

**决策:模块化单体交付核心闭环;微服务最小拆分列入延后项(迭代 5 视进度实施)**

| 考量 | 说明 |
|---|---|
| 团队与周期 | 1~3 人团队、学期周期,微服务需要注册中心/网关/多实例部署,调试成本远超收益 |
| 考核重点 | 软件工程课程考核的是**工程过程与设计能力**,而非基础设施堆叠 |
| 演进空间 | 模块化单体保持服务边界清晰,将来可按域机械拆分(见下表) |
| 答辩价值 | 进度足够时实施最小拆分证明动手能力;进度不足时论证「模块化单体 + 拆分蓝图」同样体现权衡能力 |

**微服务拆分蓝图(题目技术要求落位;延后项——进度允许时实施最小拆分)**

| 单体模块 | 未来微服务 | 说明 |
|---|---|---|
| user / security | user-service | 网关 + JWT 认证 |
| trial / evaluate | trial-service、evaluate-service | 评测计算密集,独立扩容 |
| resource | resource-service | 题库/资源 |
| classroom / live | live-service | WebSocket 长连接 |
| stats | stats-service | 统计分析 |
| — | 基础设施:Gateway + Nacos(注册/配置)+ Redis + OSS/MinIO | 拆分时配套 |

拆分原则:按业务域聚合、按变更频率分离、按资源需求拆分;**先拆数据库、再拆服务**。

## 6. AI 评测引擎设计(核心)

### 6.1 六维度 → 实现方式映射

| 题目维度 | 文本规则实现(真实可解释) | 音视频部分处理 |
|---|---|---|
| 教学内容 | 知识点覆盖度(任务配置知识点清单 × 学科术语词库命中)、五环节(导入-新授-练习-小结-作业)结构完整度、篇幅合理度 | — |
| 教学表达 | 口头禅正则检测(嗯/那个/就是/然后…)、语速估算(字数÷时长,参考 200~260 字/分)、停顿/流畅度标记 | **普通话 → 百度语音识别**:识别文本 vs 试讲稿**字错率(CER)** + 词置信度 + 通顺度(延后实施);音量 → 自评量表 + 教师评分 |
| 教姿教态 | — | **百度人体关键点识别**:抽帧 → 躯干直立度、走动幅度、手势活跃度、面向朝向(延后实施);保底:学生自评量表(10 项)+ 教师观摩评分 |
| 课堂互动与控场 | 提问句式占比(疑问句 10%~20% 为佳)、鼓励语词库命中、反馈评价词库命中、纪律管理词库命中 | — |
| 板书 / PPT | `[板书]` 标记次数与结构、PPT 环节时间分配 | 字迹工整 → 教师评分 |
| 时间管理 | 各环节实测时长 vs 任务标准配比(默认:导入 10% / 新授 40% / 练习 25% / 小结 10% / 作业 5%),超时/提前结束检测 | — |

### 6.2 规则引擎设计

- **接口抽象**:`Evaluator` 接口 → `EvaluationResult evaluate(TrialContext ctx)`,输入试讲稿 + 任务配置,输出六维分数 + 问题 + 建议。
- **默认实现** `RuleEvaluator`:纯 Java 规则,零外部依赖、结果可解释(每分都有依据,答辩友好)。
- **延后实现** `AsrEvaluator`(普通话维度):调用百度语音识别 API——音频切段(≤60s)→ 识别文本与试讲稿比对**字错率(CER)** + 词置信度 + 通顺度,规则换算为普通话分(见 6.4)。
- **延后实现** `PostureEvaluator`(教姿教态维度):FFmpeg 抽帧 → 百度人体关键点识别 → 躯干直立度、走动幅度、手势活跃度、面向朝向换算为姿态分(见 6.4)。
- **可选实现** `LlmEvaluator`:调用大模型 API(如豆包/DeepSeek)做文本语义评测,通过配置开关切换——**预留扩展点本身就是设计亮点**。
- 各实现均实现 `Evaluator` 接口,由评测引擎按维度编排聚合;API 调用失败自动回退保底规则,不影响核心闭环。
- **打分机制**:每个检测规则产出子项分(0~100),维度分 = 子项加权平均,权重来自任务的 `rubric_json`(教师可自定义评分细则,呼应题目需求 8)。
- **建议生成**:问题码 → 建议模板库,如 `ORAL_FILLER_HIGH` →「口头禅"那个"出现 23 次,建议放慢语速、用停顿替代口头禅」。

### 6.4 音视频评测流程(延后项,迭代 5)

```
试讲音视频(录制回放)
    │  ① FFmpeg 预处理:抽帧(每 2~5s 1 帧)+ 音频切段(≤60s)+ 时长提取
    ▼
百度 API 批量调用(免费额度内,失败重试 + 结果本地落库缓存)
    ├── 语音识别(ASR)──► 识别文本 + 词置信度 ──► 字错率 CER(与 script_text 比对)──► 普通话维度分
    └── 人体关键点识别 ──► 躯干角 / 重心位移 / 手腕活跃度 / 肩线朝向 ──► 教姿教态维度分
    ▼
评测引擎聚合(与 RuleEvaluator 文本维度分加权求和)──► 报告落库 + 前端雷达图
```

- **字错率 CER** =(替换 + 删除 + 插入字符数)÷ 试讲稿字数,映射为普通话分(如 CER ≤ 3% 为优秀);通顺度、ASR 置信度作为辅助指标。
- **姿态指标**:躯干与竖直方向夹角(直立度)、帧间重心位移(走动)、手腕关键点帧间位移(手势活跃度)、肩线朝向 vs 板面方向(面向学生/黑板)。
- **保底策略**:API Key 未配置、网络异常或超出额度时,自动**回退**为「自评量表 + 教师评分」,不影响核心闭环;识别结果缓存本地,答辩可离线回放。

## 7. 接口设计规范

- **RESTful**:统一前缀 `/api/v1/`,资源名词复数,JSON 交互。
- **统一响应**:`{code, message, data}`;全局异常处理器统一错误码。
- **认证**:登录返回 JWT,请求头 `Authorization: Bearer <token>`;接口按角色注解鉴权(`@PreAuthorize`)。
- **分页**:`pageNum` / `pageSize` 参数,`PageResult` 统一返回。
- **WebSocket**:`/ws/classroom` 虚拟课堂事件通道(学生行为、举手提问、教师文字点评)。
- 主要接口(示例):

| 接口 | 说明 |
|---|---|
| POST /api/v1/auth/login | 登录,返回 JWT |
| GET /api/v1/tasks | 任务列表(学生看班级任务/教师看自己发布) |
| POST /api/v1/trials | 提交试讲(试讲稿 + 环节时长) |
| POST /api/v1/trials/{id}/media | 上传试讲音视频(延后迭代) |
