# 师范专业 AI 试讲台系统 — 技术方案

> 软件工程课程设计 · v0.3(2026-09-20)
> 配套文档:[环境配置.md](./环境配置.md)

## 1. 项目概述

面向师范类专业学生的 AI 虚拟试讲训练与考核平台,用虚拟学生 + AI 多维度评测辅助/替代真实课堂试讲,覆盖课前磨课、技能训练、教学评价、达标认证全流程。

**课程设计定位**:在有限周期内实现**可演示的核心业务闭环**;对题目中的商业级技术要求(微服务、直播、AI 音视频分析)采取「分级实现 + 延后项管理」策略——核心维度真实实现(文本规则引擎,普通话/教姿教态借百度语音识别与人体分析 API),工程量大的项(直播、微服务拆分)尽力完成,进度不足则明确标注**实现延后**并给出演进设计。

全部业务用例均 `<<include>>` 公共用例 UC-C01。用例编号以**本节为唯一权威**——

> **UC-C01 为公共用例**:所有业务用例执行前均依赖身份认证,故统一 `<<include>>` UC-C01,
> 不在每个角色下重复列出「登录」;角色差异由角色控制(师范生 / 教师 / 管理员)在认证后判别。

> **专业 / 年级 / 课程的绑定口径**:题目原文要求「绑定专业、年级、课程」,本系统的落点是——
> **专业、年级**为 `sys_user` 的自身字段,由师范生本人维护(UC-S01);
> **课程**不是师范生直接绑定的对象,而是 `clazz.course` 字段,由建班者在 UC-T01「管理班级」时设定,
> 师范生经 UC-S02「加入班级」(`clazz_student`)**间接关联到课程**。
> 故本表不设「师范生绑定课程」用例——这与 §2.2「课程为 `clazz.course` 字段,不单独建表、不单设模块」的架构决策一致。

> **为什么「AI 评测」不是独立用例**:评测是 UC-S04「提交试讲」的**系统响应**,而非师范生单独发起的业务目标——
> `POST /api/v1/trials` 在**同一请求内**完成「试讲落库 → 评测计算 → 报告落库」,并把报告直接返回给前端
> 师范生无需、也无法单独触发一次评测,故本表不设该用例。
> 这与模块划分并不冲突:`evaluate` 承担计算、`report` 只做查询(见 §2.2),二者是同一次请求内的**协作**,
> 而不是两个用户用例。

> **两处覆盖缺口在此显式声明**(完整核对见 2.5):
> - 题目需求 1 的「**小组训练**」——本期降级:小组维度并入班级,任务按班级发布;迭代 3 视进度以 `clazz_group` 表补充。
> - 题目需求 8 的「**语音点评**」——本期降级:仅实现文字点评。
>
> 二者均为「明确降级 + 有演进路径」,而非遗漏。

### 2.2 题目 9 大功能 → 系统模块映射

| 题目功能 | 系统模块 | 课程设计实现程度 |
|---|---|---|
| 1 身份与课程管理 | user / clazz | 🔶 简版。**课程为 `clazz.course` 字段**,不单独建表、不单设模块(课程是无行为的枚举型字典,独立建表只增加 join 成本;将来若出现课程级配置需求,再升级为 course 字典表)。**「小组训练」降级**:小组维度并入班级(见 2.5),迭代 3 视进度以 `clazz_group` 表补充 |
| 2 AI 虚拟课堂 | classroom(简版) | 🔶 简版:虚拟学生行为用**状态机模拟**(专注/走神/举手/提问,预设互动脚本),实时互动用 WebSocket **文字事件流**呈现。降级项:3D 渲染、课堂氛围音、语音实时交互(见 2.5 第 2 组)。模块骨架已预留,`classroom_session` / `student_behavior_event` 两表迭代 4 建 |
| 3 试讲录制与直播 | trial(含录制) | 🔶 录制:音视频**文件上传** + 本地磁盘存储(模拟对象存储);直播尽力实现(录制回放 HLS + SRS 推拉流),工期不足则延后为文字观摩点评。降级项:多路独立存储改为**画中画单路合成**。录制为 trial 子包 `media`,**不单设 record 模块**(无独立表、无独立服务边界) |
| 4 AI 多维评测 | evaluate | ⭐ 核心:文本维度用**规则引擎**真实实现;**普通话**借百度**语音识别 API**(识别文本 vs 试讲稿字错率 + 置信度)、**教姿教态**借百度**人体关键点识别**真实实现(迭代 5);「自评量表 + 教师评分」保留为保底对照;预留大模型接口。降级项:音量走自评量表、字迹工整走教师评分(见 2.5 第 4 组) |
| 5 即时反馈与建议 | report | 🔶 完整:分数 + 六维雷达图 + 问题定位 + 逐条建议。**职责边界:report 只做查询与 VO 组装,不参与评测计算**(计算全部发生在 evaluate,结果落 evaluation_report 后由 report 读出)。降级项:示范片段以示例话术替代、逐句建议改为按环节/段落 |
| 6 教材与题库 | resource | ✅ 完整(CRUD + 初始化数据)。resource 含 `RUBRIC` 评分细则模板类型,供管理员维护、教师发布任务时复制进 `task.rubric_json` |
| 7 训练模式 | task(mode 字段) | 🔶 简版:四种模式 = 任务类型 + 计时规则 + 情景题,取值 `FREE` / `SCENARIO` / `STRUCTURED` / `EXAM`,定义见下表。**阶梯中的「入门:跟读训练、语音语调纠正」依赖普通话 ASR,随迭代 5 交付**;迭代 2 先交付进阶(无提示试讲)、高阶(突发情景)、考核三层 |
| 8 教师/管理员后台 | stats / review | 🔶 完整(统计、导出、排行)。管理员「自定义评分细则」落点为 `resource(type=RUBRIC)`,不新增表。降级项:**语音点评不做**,仅文字点评 |
| 9 达标与认证 | cert | 🔶 简版:证书模板生成 + 进步曲线对比(certificate 表已建,模块骨架已预留)。**「薄弱项专项训练推送」降级**为「薄弱项 → 推荐题库」列表,不做主动推送 |

**训练模式四要素定义**(与 `task.mode` 字段取值一一对应,见 `docs/init.sql`):

| 取值 | 名称 | 计时规则 | 情景脚本 | 评分标准来源 |
|---|---|---|---|---|
| `FREE` | 自由试讲 | 不限时或宽限 | 无 | 任务 `rubric_json` |
| `SCENARIO` | 情景模拟 | 限时 | **启用**(学生质疑 / 课堂混乱 / 设备故障) | 任务 `rubric_json` |
| `STRUCTURED` | 结构化面试 | 限时,按考官提问节奏 | 无(固定提问序列) | 教资面试维度 |
| `EXAM` | 模拟考核 | **严格计时 + 超时/提前结束提醒** | 无 | 考官评分标准 |

### 2.4 技术难点与实现延后清单(答辩口径)

| 技术难点 | 实现方案 | 状态 |
|---|---|---|
| 普通话标准度评测 | 百度**语音识别 API**:音频按 60s 切段循环识别 → 识别文本与试讲稿比对**字错率(CER)** + 词置信度 + 通顺度 → 规则换算为普通话维度分 | 计划实现(迭代 5);API 不可用时自动回退「自评量表 + 教师评分」 |
| 教姿教态评测(站姿/走动/手势/朝向) | 百度**人体关键点识别 API**:FFmpeg 抽帧(每 2~5s 1 帧)→ 关键点计算躯干直立度、走动幅度、手势活跃度、面向朝向;眼神用面部朝向角度近似 | 计划实现(迭代 5);同上回退 |
| 音视频直播 | 录制回放(HLS/MP4)+ SRS 开源流媒体服务推拉流,浏览器 flv.js/HLS 播放 | 尽力完成(迭代 5);工期不足则**延后**,保留文字观摩点评兜底 |
| 微服务 | 模块化单体交付核心闭环;进度允许时做**最小拆分**(evaluate-service + Gateway + Nacos,2~3 个服务,见 3.1) | 尽力完成(迭代 5);拆分蓝图论证随时可讲 |
| 大模型语义评测 | `LlmEvaluator` 扩展点,配置开关切换 | 预留接口,按需接入 |

答辩口径:**能真实实现的做扎实**(文本规则引擎 + 百度 API 音视频评测),**工期敏感的明确延后**(直播、微服务),每一处取舍都有理由、有兜底、有演进路径。

### 5.1 表归属权责(模块间读写边界)

> 本节消除「同一张表被多个模块写入」的权责歧义。**每张表有且仅有一个属主模块。**

| 表 | 属主模块(唯一写入方) | 只读 / 消费方 |
|---|---|---|
| sys_user | user | security(认证校验)、clazz(校验带班教师)、review(校验批阅人) |
| clazz | clazz | task(发布目标)、stats |
| clazz_student | clazz | task、trial(校验学生归属) |
| task | task | trial(提交时校验)、evaluate(读 rubric_json / 知识点清单)、stats |
| trial | trial | evaluate(读试讲稿 / 音视频路径 / 自评量表)、review(批阅对象)、stats |
| evaluation_report | evaluate | report(展示)、review(批阅参考)、stats(进步曲线)、cert(达标判定) |
| question_bank | resource | — |
| resource | resource | task(取 RUBRIC 评分细则模板) |
| review | review | stats |
| certificate | cert | stats |

**两条跨模块访问规则**:

- **R-1 可以跨模块读表,不可以跨模块写表。**
  模块 A 需要模块 B 的数据时,直接 `SELECT` B 的表是允许的(避免为纯查询单独开接口);
  但凡**写入**(INSERT / UPDATE / DELETE),必须调用 B 暴露的 Service 方法,**禁止直接操作 B 的表**。
- **R-2 状态字段的流转权归属主模块。**
  典型场景:`trial.status` 的 `EVALUATED` 值虽由评测结果决定,但只能由 **trial 模块**写入——
  evaluate 完成计算后调用 `TrialService.markEvaluated(trialId)`,**不得直接 `UPDATE trial`**。
  同理 `task.status` 的 `CLOSED` 只能由 task 模块写入。

**无表模块**(不拥有任何表,职责仍须明确):

| 模块 | 职责 | 约束 |
|---|---|---|
| report | 评测报告查询与 VO 组装 | 只读;禁止注入 `Evaluator` / `EvaluationEngine`,禁止参与评测计算 |
| stats | 跨模块只读聚合(看板 / 导出 / 排行 / 进步曲线) | 只读;不拥有表,不得为统计新建表 |
| security | JWT 签发与校验、登录用户上下文 | 不拥有业务表;登录业务(密码校验、用户查询)归 user 模块 |

> **登录接口归属定案**:`POST /api/v1/auth/login` 由 **user 模块**实现(`AuthController`),
> security 模块只提供 `JwtUtil` 工具与 `JwtAuthenticationFilter`。
> UserController 注释中「或独立 AuthController」的待定项以此为准。

### 5.2 关系与索引

**关系**:教师 1—N 班级 1—N 任务 1—N 试讲 1—1 报告;试讲 1—N 批阅;学生 N—N 班级。
> 注意:`task` 挂 `clazz_id` 而非 `teacher_id`,「教师 → 任务」是**经班级间接成立**的(教师 1—N 班级,班级 1—N 任务),
> 而非直接外键。`task.created_by` 固化实际发布人,班级更换带班教师时历史任务的归属不漂移。

**索引**:全库二级索引均以 `idx_`(普通) / `uk_`(唯一) 命名,并在 `init.sql` 中**逐条注释其服务的查询**。
关键几条:(task_id, student_id) 试讲提交与查重、(student_id, created_at) 学生历史与进步曲线、
(clazz_id, student_id) 班级学生与防重复入班、(created_by) 教师任务列表、(type, subject) 资源筛选、(teacher_id) 批阅统计、
(student_id) / (task_id) 证书列表与达标统计。
> 组合索引已覆盖其最左列的单列查询(如 `uk_clazz_student` 覆盖 `clazz_id`),**不得再冗余单建单列索引**。

**类型约定**(完整规约见 [数据库设计规范.md](./数据库设计规范.md)):
所有 JSON 数据用 MySQL 原生 `JSON` 类型(`rubric_json` / `stage_times_json` / `self_assessment_json` /
`dimension_scores_json` / `issues_json` / `suggestions_json` / `media_analysis_json`,共 7 列),
**写入时即校验格式**——写坏的 JSON 当场报 `ERROR 3140`,不会留到评测时才炸;时间列一律 `DATETIME`(不用 `TIMESTAMP`);
主键一律 `BIGINT` 有符号(不用 `UNSIGNED`,与 Java `Long` 精确对应)。

| 教学表达 | 口头禅正则检测(嗯/那个/就是/然后…)、语速估算(字数÷时长,参考 200~260 字/分)、停顿/流畅度标记 | **普通话 → 百度语音识别**:识别文本 vs 试讲稿**字错率(CER)** + 词置信度 + 通顺度(延后实施);音量 → 自评量表 + 教师评分 |
| 教姿教态 | — | **百度人体关键点识别**:抽帧 → 躯干直立度、走动幅度、手势活跃度、面向朝向(延后实施);保底:学生自评量表(10 项)+ 教师观摩评分 |
| 课堂互动与控场 | 提问句式占比(疑问句 10%~20% 为佳)、鼓励语词库命中、反馈评价词库命中、纪律管理词库命中 | — |

### 6.2 规则引擎设计

- **接口抽象**:`Evaluator` 接口 → `Map<Dimension,Integer> contributions()`(声明负责的维度及维度内贡献权重)+ `EvaluationResult evaluate(TrialContext ctx)`(输出分数/问题/建议)。
  **维度标识由 `Dimension` 枚举唯一定义**(6 维),禁止硬编码维度字符串。
- **维度贡献模型**:一个评测器可负责多个维度,一个维度也可由多个评测器**共同贡献**。例如「教学表达」在迭代 2 由 `RuleEvaluator` 按口头禅/语速打分(权重 60),迭代 5 起再由 `AsrEvaluator` 按普通话字错率打分(权重 40),二者加权合并而非二选一。
- **默认实现** `RuleEvaluator`:纯 Java 规则,零外部依赖、结果可解释(每分都有依据,答辩友好)。
- **延后实现** `AsrEvaluator`(普通话维度):调用百度语音识别 API——音频切段(≤60s)→ 识别文本与试讲稿比对**字错率(CER)** + 词置信度 + 通顺度,规则换算为普通话分(见 6.4)。
- **延后实现** `PostureEvaluator`(教姿教态维度):FFmpeg 抽帧 → 百度人体关键点识别 → 躯干直立度、走动幅度、手势活跃度、面向朝向换算为姿态分(见 6.4)。
- **可选实现** `LlmEvaluator`:调用大模型 API(如豆包/DeepSeek)做文本语义评测,通过配置开关切换——**预留扩展点本身就是设计亮点**。
- 各实现均实现 `Evaluator` 接口,由评测引擎按维度编排聚合;API 调用失败自动回退保底规则,不影响核心闭环。
- **打分机制**:每个检测规则产出子项分(0~100)。层级聚合由 `EvaluationEngine` 统一执行:
  - **维度分** = Σ(各评测器该维度得分 × 贡献权重) ÷ Σ(已产出该维度分的评测器权重)。
    某评测器未接入或未产出该维度分时**按剩余权重自动归一化**——这正是「百度 API 不可用时回退保底方案」的实现机制,引擎无需为此写特判。
  - **总分** = Σ(维度分 × 维度权重) ÷ Σ(维度权重),权重取自任务的 `rubric_json`(教师可自定义评分细则,呼应题目需求 8)。
    **未产出分数的维度不参与计算**——否则迭代 2 尚无教姿教态分时会被记 0 分,导致总分不公。
  - 评测器返回**未声明或未知**维度时告警并忽略该条,防止契约漂移。
- **建议生成**:问题码 → 建议模板库,如 `ORAL_FILLER_HIGH` →「口头禅"那个"出现 23 次,建议放慢语速、用停顿替代口头禅」。

```json
  "issues": [
    {"dimension": "expression", "level": "WARN", "title": "口头禅过多", "detail": "…", "suggestion": "…"}
  ]
}
```

> **维度 key 取值受控**:`dimensions[].key` 与 `issues[].dimension` 的取值必须是 `Dimension` 枚举的 6 个 key
> (`content` / `expression` / `posture` / `interaction` / `board` / `time`),前端雷达图按此固定顺序渲染。

**「未评测」与「0 分」必须区分**(`EvaluationResult.evaluated()`):

当没有任何评测器产出维度分时,`totalScore` 为 0,但语义是**尚未评测**而非得了 0 分。
若不加区分,会造成:进步曲线出现虚假的 0 分低谷、班级平均分被未评测的试讲拉低、达标判定把「还没测」误判为「不达标」。

- 判定方式:`EvaluationResult.evaluated()`(派生自 `dimensions` 是否为空,**不序列化到 JSON**,避免冗余字段)
- **落库前必须判断**:未评测时不得写入 `evaluation_report` 表——该表 `total_score` 为 `NOT NULL`,一旦写入即被当作真实分数;
  应抛 `BizException` 提示「评测未完成」
- 不变量:只要有任何评测器产出一个维度分(即使该维度分为 0),即属于「已评测」

前端用 ECharts 渲染雷达图 + 问题列表。

### 6.4 音视频评测流程(延后项,迭代 5)

```
试讲音视频(录制回放)
    │  ① FFmpeg 预处理:抽帧(每 2~5s 1 帧)+ 音频切段(≤60s)+ 时长提取
    ▼
百度 API 批量调用(免费额度内,失败重试 + 结果本地落库缓存)
    ├── 语音识别(ASR)──► 识别文本 + 词置信度 ──► 字错率 CER(与 script_text 比对)──► 普通话维度分
    └── 人体关键点识别 ──► 躯干角 / 重心位移 / 手腕活跃度 / 肩线朝向 ──► 教姿教态维度分
    ▼
评测引擎聚合(与 RuleEvaluator 文本维度分加权求和)──► 报告落库 + 前端雷达图
```

- **字错率 CER** =(替换 + 删除 + 插入字符数)÷ 试讲稿字数,映射为普通话分(如 CER ≤ 3% 为优秀);通顺度、ASR 置信度作为辅助指标。
- **姿态指标**:躯干与竖直方向夹角(直立度)、帧间重心位移(走动)、手腕关键点帧间位移(手势活跃度)、肩线朝向 vs 板面方向(面向学生/黑板)。
- **保底策略**:API Key 未配置、网络异常或超出额度时,自动**回退**为「自评量表 + 教师评分」,不影响核心闭环;识别结果缓存本地,答辩可离线回放。
  - **自评量表数据归属**:存于 `trial.self_assessment_json`(学生提交试讲时一次性录入,与试讲 1:1),评测时经 `TrialContext.selfAssessment` 传入。**不新建表**——自评是评测的**输入**而非输出,放 `evaluation_report` 语义错误,放 `review` 表则与该表 `teacher_id NOT NULL` 的教师批阅语义冲突。若将来需按维度聚合自评分以支撑「薄弱项专项训练推送」,再拆 `trial_self_assessment` 独立表。

> **技术债留痕:慢评测与同步返回的张力**。本节流程含百度 API **批量调用**(多次请求 + 失败重试),
> 耗时远高于文本规则引擎。迭代 2 的规则评测在 `POST /api/v1/trials` 内**同步完成没有问题**;
> 但迭代 5 接入 ASR / 姿态评测后,若仍同步执行会导致请求超时。
> 届时**二选一**:① 提交后**异步评测** + 前端轮询报告状态;② 新增**显式的重评测接口**由用户触发。
> 该选择属迭代 5 的设计决策,**现在不做实现**;此处留痕,以免答辩被问「慢评测如何同步返回」。

## 7. 接口设计规范

- **RESTful**:统一前缀 `/api/v1/`,资源名词复数,JSON 交互。
- **统一响应**:`{code, message, data}`;全局异常处理器统一错误码。
  **`data` 键始终存在**(无数据时为 `null`)——`application.yml` 的 `default-property-inclusion: non_null` 会令 null 字段整个消失,
  故 `Result.data` 上显式标注 `@JsonInclude(ALWAYS)` 覆盖全局配置,保证契约字面成立。
- **认证**:登录返回 JWT,请求头 `Authorization: Bearer <token>`;接口按角色注解鉴权(`@PreAuthorize`)。
- **分页**:`pageNum` / `pageSize` 参数,`PageResult` 统一返回。
- **WebSocket**:`/ws/classroom` 虚拟课堂事件通道(学生行为、举手提问、教师文字点评)。

**错误通道(前端必读)**:错误有**两条通道**,前端 `api/request.js` 必须同时处理——

| 通道 | 触发位置 | HTTP 状态 | 响应体 | 前端处理 |
|---|---|---|---|---|
| 业务错误 | Controller / Service(`BizException`、参数校验失败) | **恒为 200** | `Result{code≠0, message}` | 判 `code ≠ 0` 后提示 `message` |
| 认证 / 授权错误 | Spring Security 过滤器链(JWT 缺失或过期) | **401 / 403** | 非 `Result` 结构(由 Security 直接返回) | 拦截器按 HTTP 状态码跳登录页 |

> 原因:`@RestControllerAdvice` 只覆盖 Controller 层;过滤器链先于 DispatcherServlet 执行,其拒绝响应不经过异常处理器。
> 前端**不能只判 HTTP 状态码**(业务错误都是 200),**也不能只判 `code`**(401 响应体里没有 `code` 字段)。

- 主要接口(示例):

| 接口 | 说明 |
|---|---|
| POST /api/v1/auth/login | 登录,返回 JWT |
| GET /api/v1/tasks | 任务列表(学生看班级任务/教师看自己发布) |
| POST /api/v1/trials | 提交试讲(试讲稿 + 环节时长);**同一请求内自动完成评测,直接返回报告** |
| POST /api/v1/trials/{id}/media | 上传试讲音视频(延后迭代) |
| GET /api/v1/reports/{trialId} | 重新查看评测报告(报告已在提交试讲时生成) |
| POST /api/v1/reviews | 教师批阅打分点评 |
| GET /api/v1/stats/class/{id} | 班级数据看板 |
| GET /api/v1/stats/export | 成绩导出(Excel) |
