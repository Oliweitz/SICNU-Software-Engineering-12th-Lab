## 1. 环境要求

| 项 | 版本要求 | 说明 |
|---|---|---|
| JDK | 17+(建议 21 LTS) | 编译目标 Java 17(pom 中 `--release 17`),更高版本同样兼容 |
| Maven | 3.9+ | 依赖下载建议配置国内镜像(见第 6 节) |
| MySQL | 8.x(必需) | 初始化脚本 `docs/init.sql`(建库 + 建表 + 种子数据) |
| Node.js | 20 LTS+(采用 Vue 前端时必需) | 见 3.2 |
| Redis | 可选 | 题目技术要求包含;可先用内存缓存代替,后期按需引入 |
| IDE | IntelliJ IDEA / VS Code | 需启用 Lombok 注解处理 |

快速验证:

```bash
mvn -version    # 确认 JDK 17+、Maven 3.9+

```

## 3. 组件安装指引

### 3.1 MySQL 8.x(必需)

- 安装包:https://dev.mysql.com/downloads/installer/ (MySQL Installer,选 Server only)
- 绿色版/免安装版也可;记下 **root 密码**和端口(默认 3306)
- 初始化时执行 `docs/init.sql`(建库 `ai_trial_platform` + 建表 + 种子数据)

**⚠️ `init.sql` 含 `DROP DATABASE IF EXISTS ai_trial_platform`,重跑会清空同名库的全部数据。**
它只用于全新环境初始化;**库已建好时不要重跑**。动手前先确认:

```bash
mysql -u root -p -e "SHOW DATABASES LIKE 'ai_trial_platform';"
```

**Windows 服务默认不自启**:MySQL Installer 装出来的服务(名为 `MYSQL80`)启动类型是**手动**,
重启电脑后不会自己起来,症状与下面的「密码不对」几乎一样。建议一次性设成自动(需管理员 PowerShell):

```powershell
Set-Service MYSQL80 -StartupType Automatic
```

**root 密码不是 `root` 时必须覆盖**:应用按 `application-dev.yml` 的 `${DB_PASSWORD:root}` 取密码,
不设就用默认值 `root`。若你安装时设了别的密码,启动日志会**一切正常**,但 `/actuator/health` 会
**卡满 30 秒**(HikariCP 连接超时)后返回 `"db":{"status":"DOWN"}`——真实原因
`Access denied for user 'root'@'localhost'` 只藏在 health 端点里,启动日志看不到。

```powershell
# Windows:写入用户级环境变量,之后新开的终端自动生效(无需管理员)
[Environment]::SetEnvironmentVariable("DB_PASSWORD","你的密码","User")
```

```bash
# Git Bash / Linux / macOS
export DB_PASSWORD=你的密码
```

> 环境变量在**进程启动时读取一次**,不是实时生效:`mvn spring-boot:run` 需**新开终端**,
> IDEA 需**完全重启**(不是关项目,是退出程序——它有启动时读一次的环境缓存)。
> 不想重启 IDEA,可在 `Run/Debug Configurations` → `Environment variables` 里直接填 `DB_PASSWORD=你的密码`。

### 3.2 Node.js 20 LTS +(采用 Vue 前端时必需,推荐)

- 下载:https://nodejs.org/zh-cn (选 LTS)

- 验证:`node -v`、`npm -v`

## 5. 一键启动流程(目标)

```bash
# 0. 配置数据库密码(仅当 root 密码不是默认的 root,见 3.1)
export DB_PASSWORD=你的密码

# 1. 初始化数据库(仅首次;⚠️ 脚本含 DROP DATABASE,库已存在时不要执行)
mysql -u root -p < docs/init.sql

# 2. 启动后端(8080),在仓库根目录执行
mvn spring-boot:run

# 3. 启动前端(5173,开发模式)
cd frontend && npm install && npm run dev

# 4. 浏览器访问 http://localhost:5173
```

> **PowerShell 不支持 `<` 输入重定向**(报「`<`运算符是为将来使用而保留的」)。
> 第 1 步改用 mysql 客户端内置的 `source`:
> `mysql -u root -p -e "source docs/init.sql"`;
> 第 0 步写成 `$env:DB_PASSWORD="你的密码"`。

**启动后端后的自检**:`curl.exe http://localhost:8080/actuator/health`(PowerShell 里 `curl`
是 `Invoke-WebRequest` 的别名,必须写 `curl.exe`),预期返回 `{"status":"UP",...,"db":{"status":"UP"}}`
且耗时毫秒级。若 `db` 为 `DOWN` 且耗时约 30 秒,见 3.1 的密码说明。

## 6. 常见问题

| 问题 | 处理 |
|---|---|
| 依赖下载慢 | Maven 配置阿里云镜像(settings.xml 中将 central 镜像指向 `https://maven.aliyun.com/repository/public`);npm 用 npmmirror(见 3.2) |
| 端口 8080 / 3306 被占用 | 改 `application.yml` 中端口;查占用 `netstat -ano \| findstr 8080` |
| **PowerShell 里执行 `mysql -u root -p < docs/init.sql` 报「`<`运算符是为将来使用而保留的」** | PowerShell 不支持 `<` 输入重定向(Linux / Git Bash 语法)。改用 mysql 客户端内置的 `source`:`mysql -u root -p -e "source docs/init.sql"`。**不要**用 `Get-Content docs/init.sql \| mysql`——PowerShell 管道会按自身编码重新编码,含中文的种子数据必乱码 |
| **启动日志一切正常,但 `/actuator/health` 卡满 30 秒后返回 `"db":{"status":"DOWN"}`** | HikariCP 连接超时,真实原因 `Access denied for user 'root'@'localhost'` 只在 health 端点里,启动日志看不到。绝大多数是 **`DB_PASSWORD` 没覆盖**(应用默认用 `root/root`,见 3.1)。改完必须**完全重启终端 / IDEA**——环境变量在进程启动时只读取一次 |
| **重启电脑后上述症状重现** | MySQL 的 Windows 服务(`MYSQL80`)默认**手动启动**,不会自启。管理员 PowerShell 执行 `net start MYSQL80` 临时启动,或 `Set-Service MYSQL80 -StartupType Automatic` 一劳永逸 |
| **重跑 `init.sql` 后原有数据全没了** | 脚本开头即 `DROP DATABASE IF EXISTS ai_trial_platform`,设计如此。库已有数据的环境请走 `docs/migration/` 下的增量脚本(当前最新为 `V2__data_dict.sql`,不含 `DROP` 且可重复执行),不要重跑 init.sql |
| 中文乱码 | 工程统一 UTF-8(pom 中 `project.build.sourceEncoding`);MySQL 连接串加 `characterEncoding=utf8`;IDE 设置 UTF-8 |
| **执行 init.sql 报 `ERROR 1366 Incorrect string value`,或建出来的表注释乱码** | Windows 中文环境下 mysql 客户端默认 `character_set_client=gbk`,会把 UTF-8 脚本当 GBK 解读。`init.sql` 开头已加 `SET NAMES utf8mb4` 自动修正,**无需额外参数**;若手工执行其他含中文的 SQL,显式带上 `--default-character-set=utf8mb4`(查询同理,否则中文显示为乱码) |
| JDK 版本问题 | 项目编译目标 Java 17,开发机 JDK 须为 17+;21/24 等更高版本同样兼容 |
| **JDK 23+ 下 `@SpringBootTest` 启动失败**(报 `Could not initialize inline Byte Buddy mock maker` / `Could not self-attach to current VM`) | SpringExtension 会初始化 Mockito,其 inline mock maker 需动态 attach agent,JDK 23+ 默认收紧该机制。**两种解法**:①**推荐**——测试改用**手写桩**而非 Mockito(见 `module/evaluate/EvaluationEngineTest`,零依赖、更快、可读性更好);② 需要 Mockito 时,在 surefire 中把 byte-buddy-agent 配成 `-javaagent` 显式加载 |
| 依赖 Lombok 的类编译后 getter/setter 全部缺失,且**不报错** | JDK 23+ 不再隐式运行注解处理器。`pom.xml` 已显式配置 `<proc>full</proc>`,请勿删除该配置 |
| 提交被钩子拒绝 | 提交信息格式不符,按提示修改;规范见 Git工作流与提交规范.md 第 3 节 |
| `mvn spotless:check` 失败 | 先执行 `mvn spotless:apply` 格式化后再提交 |

Maven 镜像配置示例(`~/.m2/settings.xml`,仅需配置一次):

```xml
<settings>
  <mirrors>
    <mirror>
      <id>aliyun</id>
      <name>Aliyun Central Mirror</name>
      <url>https://maven.aliyun.com/repository/public</url>
      <mirrorOf>central</mirrorOf>
    </mirror>
  </mirrors>
</settings>
```
