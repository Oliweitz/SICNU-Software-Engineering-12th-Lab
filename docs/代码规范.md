# 代码规范

> 软件工程课程设计 · 2026-09
> 适用对象:全体组员;评审时本规范本身也是"工程过程"的体现
> 配套文档:[技术方案.md](./技术方案.md)、[Git工作流与提交规范.md](./Git工作流与提交规范.md)

本规范基于《阿里巴巴 Java 开发手册》与 Google Java Style 精简而来,只保留课程设计必须执行的条目。
**原则:先格式化、后人工审查;工具能管的交给工具,人只做工具做不了的事。**

---

## 0. 工具强制(最低成本、最高收益)

| 工具 | 命令 | 时机 |
|---|---|---|
| Spotless(Google Java Format AOSP 风格,4 空格缩进) | `mvn spotless:apply` | **每次提交前必做** |
| EditorConfig | IDE 自动生效 | 首次打开项目 |
| commit-msg 钩子 | `git config core.hooksPath .githooks` | 首次 clone 后执行一次 |
| 单元测试 | `mvn test` | 每次提交前必过 |

> 代码格式不通过 `mvn spotless:check` 的提交,评审时一律要求重做。

## 1. 命名

| 对象 | 规则 | 正例 | 反例 |
|---|---|---|---|
| 类/接口 | UpperCamelCase | `TaskService`、`RuleEvaluator` | `taskService` |
| 方法/变量 | lowerCamelCase | `getReport`、`totalScore` | `GetReport`、`total_score` |
| 常量 | 全大写下划线 | `MAX_UPLOAD_SIZE` | `maxUploadSize` |
| 包名 | 全小写,业务域分包 | `com.example.module.user` | `com.example.User` |
| 布尔变量 | 禁止 `is` 开头(避免 Lombok/序列化坑) | `deleted`、`enabled` | `isDeleted` |
| 表/字段 | 小写下划线;表名单数;必备 `id/created_at/updated_at/deleted` | `sys_user`、`task_id` | `Task`、`taskId` |

约定俗成缩写可直接使用:`DTO`、`JWT`、`IPage`、`pageNum`。

## 2. 分层与职责(四层结构)

```
Controller → Service(接口 + 实现) → Mapper → DB
```

| 层 | 职责 | 禁止事项 |
|---|---|---|
| Controller | 参数校验(`@Valid`)、调用 Service、返回 `Result<T>` | 写业务逻辑;直接调 Mapper;**直接返回裸数据** |
| Service | 业务逻辑、事务(`@Transactional`)、抛 `BizException` | 操作 HttpServletRequest/Session |
| Mapper | 单表 SQL(注解或 XML) | 写业务逻辑;跨表复杂查询用 XML 而不是 Service 循环拼装 |
| Entity | 与表结构一一对应 | 作为接口入参/出参传给前端 |

**DTO 与 Entity 分离**:接口入参用 `XxxDTO`(带校验注解),出参用 `XxxVO`,禁止将 Entity 直接暴露给前端。

## 3. 异常与日志

```java
// ✅ 业务错误:抛 BizException,由全局异常处理器统一转 Result
if (task == null) {
    throw new BizException(ResultCode.NOT_FOUND, "任务不存在");
}

// ❌ 禁止:Controller 里 try-catch 后手动拼 Result
```

- 日志门面统一 SLF4J,声明方式:`@Slf4j`。
- 级别约定:`debug` 调试细节、`info` 关键流程(登录、评测完成)、`warn` 业务异常、`error` 系统异常(必须带堆栈)。
- 禁止:`System.out.println`、`e.printStackTrace()`。
- 打印日志必须带业务上下文(如 `userId={}`),禁止只打"出错了"。

## 4. 注释与文档

- **公共类、公共方法必须有 Javadoc**:说明用途、参数约束、返回值;业务关键逻辑(如评测打分规则)必须解释"为什么"。
- 禁止无意义注释(`// 设置 name`)、禁止注释掉的大段代码(用 Git 历史代替,提交前删除)。
- 实体字段、表字段用 SQL `COMMENT` 说明含义(见 `docs/init.sql`)。
- 对外接口变更必须同步更新 `docs/技术方案.md` 第 7 节。

## 5. SQL 与数据库规范

- 禁止 `SELECT *`;禁止字符串拼接 SQL(MyBatis 一律 `#{}`)。
- 表与字段的命名、类型、索引、注释规约见 [数据库设计规范.md](./数据库设计规范.md)(该文为权威);本文件不重复约定。
- 所有表必须含 `id`(BIGINT 自增)、`created_at`、`updated_at`、`deleted`(逻辑删除),按 `docs/init.sql` 执行。
  **豁免**:纯关系表(`clazz_student`)可省 `updated_at`/`deleted`,只增不改的业务表(`certificate`)可省 `updated_at`;
  豁免须在《数据库设计规范》第 3 节白名单登记,未登记者评审不通过。
- 索引跟随查询路径:联表查询条件、`ORDER BY` 字段必须建索引(见技术方案 5 节索引设计)。
- 每次变更表结构:先改 `docs/init.sql`,再改本地库,并在提交信息中注明(周报与提交记录对应)。

## 6. 前后端契约(接口规范)

- 统一前缀 `/api/v1/`,资源名词复数,JSON 交互,统一响应 `{code, message, data}`。
- 分页入参 `pageNum`/`pageSize`,出参 `PageResult{total, records}`。
- 认证:`Authorization: Bearer <token>`;按角色鉴权用 `@PreAuthorize("hasRole('TEACHER')")`。
- 错误码表见 `ResultCode` 枚举,新增错误码必须同步更新其注释。

## 7. 前端规范(迭代 2 引入 Vue 工程后执行)

- 工程:`Vue 3 + Vite + Element Plus + Pinia + Axios + ECharts`,组合式 API `<script setup>`。
- 目录按功能分包:`views/`(页面)、`components/`(组件)、`api/`(接口封装)、`stores/`(Pinia)。
- 所有 HTTP 请求经 `api/request.js` 统一封装(携带 token、统一错误提示),禁止页面内裸写 `axios`。
- 组件命名多单词(`TrialSubmitDialog`),避免与 HTML 标签冲突。
- 样式:优先 Element Plus 组件 + 局部 `<style scoped>`,不引入整页内联样式堆砌。

## 8. 测试规范

- 测试类与被测类同包(`src/test/java` 镜像 `src/main/java` 结构),命名 `XxxTest`。
- 必须覆盖:公共组件(`common/`)、核心业务逻辑(评测引擎规则、权限判断)。
- 每个测试方法用 `@DisplayName("中文描述")`,描述"什么场景→期望什么结果"。
- Controller/Service 集成测试可用 `@SpringBootTest + @Transactional` 自动回滚;测试数据不得依赖手工插入。
- 提交前 `mvn test` 必须全绿;测试坏了先修测试,禁止注释掉断言。

## 9. 评审清单(PR / 组内互查)

- [ ] `mvn spotless:check` 通过
- [ ] `mvn test` 全绿
- [ ] Controller 返回 `Result<T>`,参数有校验注解
- [ ] 业务错误抛 `BizException`,无吞异常/裸 catch
- [ ] 无 `System.out`、无注释掉的大段代码
- [ ] 新表/新字段已同步 `docs/init.sql`
- [ ] 接口变更已同步 `docs/技术方案.md` 第 7 节
