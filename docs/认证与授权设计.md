# 认证与授权设计

> 本文档是「身份验证 / 权限验证」需求的落地方案与验收说明。
> 代码位置：后端 `src/main/java/com/example/module/user/`、`com/example/security/`、`com/example/config/SecurityConfig.java`；
> 前端 `frontend/src/views/`、`frontend/src/router/`、`frontend/src/stores/auth.ts`。
> 接口变更须同步 [技术方案.md](./技术方案.md) 第 7 节。

## 1. 需求对照

| 课程要求 | 本项目实现 | 验收方式 |
|---|---|---|
| 登录流程：提交密码 → 查用户取盐 + 哈希 → 慢哈希重算比对 → 签发会话凭证 | `POST /api/v1/auth/login`：图形验证码 → 按 `username` 查 `sys_user` → `BCryptPasswordEncoder.matches`（内部取盐并慢哈希重算）→ 签发 JWT | 密码登录成功返回 `token`；错误密码统一提示「用户名或密码错误」 |
| 统一身份认证与手机号验证的技术栈 | Spring Security + JWT + BCrypt + Hutool Captcha；短信/邮件验证码通道可插拔（mock / HTTP / SMTP）；CAS 3.0（mock 模拟 / real 对接学校） | 见本文第 2、3 节 |
| 至少两种登录方式（统一身份认证、用户密码、短信、邮件），模仿禅道 | **四种**：账号密码、手机短信验证码、邮箱验证码、统一身份认证（模拟 CAS） | 登录页三个入口 + SSO 按钮；浏览器 E2E 已逐项跑通 |
| 登录验证码至少一种形式 | 图形验证码（Hutool 线段干扰，一次性，5 分钟） | `GET /api/v1/auth/captcha`；密码登录、发送短信/邮箱验证码、注册均校验 |
| 注册、忘记密码及提示信息 | `POST /api/v1/auth/register`、`POST /api/v1/auth/password/reset`，发送验证码接口统一提示 | 见本文第 5 节「统一提示」表 |
| 权限验证 | RBAC：用户 → 角色 → 权限码；`@PreAuthorize` + 每请求回查权限；前端路由守卫与权限码渲染 | 学生访问管理员接口返回 HTTP 403；`GET /api/v1/rbac/me` 返回权限集合 |

## 2. 技术栈

| 能力 | 选型 | 说明 |
|---|---|---|
| 认证框架 | Spring Security 6（Spring Boot 3.5.4） | 无状态会话、过滤器链、方法级鉴权 |
| 会话凭证 | JWT（jjwt 0.12.6，HMAC-SHA） | 载荷只放 `id / username / realName`，权限每请求回查，授权调整即时生效 |
| 密码哈希 | `BCryptPasswordEncoder`（强度 10） | 慢哈希 + 随机盐；**盐内嵌在哈希串中**，无需额外 salt 列 |
| 图形验证码 | Hutool Captcha 5.8.32 | 130×44 线段干扰；内存存储、一次性、5 分钟过期 |
| 短信验证码 | `SmsSender` 可插拔 | `mock`（默认，验证码打日志）/ `http`（自建网关，JSON POST） |
| 邮件验证码 | `EmailCodeSender` 可插拔 | `mock`（默认）/ `smtp`（`spring-boot-starter-mail` + `spring.mail.*`） |
| 统一身份认证 | CAS 3.0 协议 | `mock` 内置模拟登录页；`real` 对接学校 CAS Server 的 `/serviceValidate` |
| 验证码存储 | 进程内 `ConcurrentHashMap` | 课程规模够用；多实例部署时替换为 Redis（接口不变） |
| 前端 | Vue 3 + Vite + Element Plus + Pinia + Axios | 登录/注册/找回密码/SSO 回调/工作台；路由守卫 + 401 自动跳转 |

### 2.1 关于「取盐 + 哈希」

`sys_user.password` 中存的是 BCrypt 字符串，格式形如：

```
$2a$10$N9qo8uLOickgx2ZMRZoMyeIjZAgcfl7p92ldGxad68LJZdL17lhWy
 └┬┘└┬┘└──────────────────────┬───────────────────────────┘
  │  │                      盐 + 哈希（BCrypt 内部编码）
  │  └ 代价因子（2^10 轮，慢哈希）
  └ 算法版本
```

登录时 `passwordEncoder.matches(明文, 哈希)` 会从哈希串中**取出盐和代价因子**，对明文重新做慢哈希，
再与库中哈希做常量时间比较。因此不需要、也不应该单独增加 `salt` 列。

## 3. 登录流程

### 3.1 账号密码登录

```
浏览器                     AuthController/AuthService              DB / Spring Security
  │ POST /auth/captcha               │                                   │
  │─────────────────────────────────>│ 生成 UUID + 图形验证码（内存 5min）│
  │<─────────────────────────────────│                                   │
  │ POST /auth/login                 │                                   │
  │  {username,password,captchaId,   │                                   │
  │   captchaCode}                   │                                   │
  │─────────────────────────────────>│ 1. 校验图形验证码（一次性）         │
  │                                  │ 2. 检查失败锁定（5 次 / 15 分钟）   │
  │                                  │ 3. 按 username 查 sys_user ───────>│
  │                                  │ 4. BCrypt matches（取盐 + 慢哈希）  │
  │                                  │ 5. 回查角色/权限码 ───────────────>│
  │                                  │ 6. 签发 JWT（24h）                  │
  │<─────────────────────────────────│ {token, roles, permissions, ...}   │
```

安全点：

- 用户不存在与密码错误返回**同一提示**「用户名或密码错误」，不泄露账号是否存在。
- 连续失败 5 次锁定 15 分钟（`auth.login.max-failures` / `lock-minutes`），不存在的登录名同样计数。
- 图形验证码一次性使用；密码明文不落库、不写日志。

### 3.2 短信 / 邮箱验证码登录

```
POST /auth/code/send {target, scene=LOGIN, captchaId, captchaCode}
  → 图形验证码校验
  → 判断 target 是手机号还是邮箱
  → 若该联系方式未绑定账号：返回统一提示，不实际发送（防账号枚举）
  → 否则生成 6 位验证码（5 分钟、最多校验 5 次、60 秒重发冷却）并发送
POST /auth/login/code {target, code}
  → 校验验证码（一次性）→ 查用户 → 签发 JWT
```

开发环境默认走 mock 通道，验证码打印在后端日志；同时 `auth.code.expose-in-response=true`
会把验证码放在响应的 `debugCode` 字段，方便前后端联调与课堂演示。**生产必须关闭该开关并配置真实通道。**

### 3.3 统一身份认证（模拟 CAS）

```
前端 window.location = /api/v1/auth/cas/login
  → 302 到模拟 CAS 登录页（mock）或学校 CAS（real），携带 state
  → 用户输入学号/工号 + 密码（mock 用本地 sys_user 校验）
  → 302 回 /api/v1/auth/cas/callback?ticket=ST-xxx&state=xxx
  → 校验 state 与 ticket（一次性、2 分钟）
  → 302 到前端 /sso-callback?ticket=<本地一次性票据>
  → 前端 POST /api/v1/auth/cas/exchange {ticket}
  → 校验本地票据 → 按学号/工号查本地用户 → 签发 JWT
```

设计要点：

- **长期 JWT 不出现在 URL 中**：回调只带 2 分钟有效、一次性的本地票据，降低浏览器历史/代理日志泄露风险。
- `state` 防 CSRF；回调地址与配置的 `auth.cas.service-url` 同源同路径校验，防开放重定向。
- `mock` 模式用于开发/答辩演示；`real` 模式把 `auth.cas.mode` 改为 `real` 并配置
  `auth.cas.server-url`，即按 CAS 3.0 的 `/serviceValidate` 校验学校返回的 `cas:user`。
- 统一认证只做**身份确认**，账号必须在本地 `sys_user` 存在并已绑定角色，不会自动创建账号。

## 4. 图形验证码

- 接口：`GET /api/v1/auth/captcha` → `{captchaId, image, expireSeconds, debugCode?}`
- 图片为 `data:image/png;base64,...`，前端直接作为 `<img src>`；点击图片刷新。
- 服务端只存 `captchaId → (code, expireAt)`，**校验一次即删除**，不区分成功失败。
- 使用场景：密码登录、发送短信/邮箱验证码、注册。
- 生产环境 `auth.captcha.expose-in-response=false`，接口不返回 `debugCode`。

## 5. 注册与找回密码

### 5.1 注册

`POST /api/v1/auth/register`：

| 字段 | 规则 |
|---|---|
| `username` | 4-50 位字母/数字/下划线，全局唯一（学号/工号） |
| `realName` | 必填 |
| `phone` | 必填，`1[3-9]` 开头 11 位，必须通过短信验证码验证归属，全局唯一 |
| `smsCode` | 场景 `REGISTER` 的短信验证码 |
| `email` + `emailCode` | 选填；填写邮箱时必须通过邮箱验证码验证归属，全局唯一 |
| `major` / `grade` | 选填，填字典码（`CHINESE_EDU` / `2024` 等） |
| `password` / `confirmPassword` | 6-32 位，两次一致 |
| `captchaId` / `captchaCode` | 图形验证码 |

注册成功后默认分配 `STUDENT` 角色；密码 BCrypt 加密后入库。用户名、手机号、邮箱重复返回明确的冲突提示。

### 5.2 找回密码

```
POST /auth/code/send {target, scene=RESET_PASSWORD, captcha...}
  → 账号不存在也返回「如果该账号已绑定联系方式，验证码已发送」，不实际发送
POST /auth/password/reset {target, code, newPassword, confirmPassword}
  → 校验验证码 → 更新 BCrypt 密码 → 清除失败锁定
```

### 5.3 统一提示（不可含糊）

| 场景 | 提示 | HTTP |
|---|---|---|
| 密码错误 / 用户不存在 | 用户名或密码错误 | 401 |
| 验证码登录失败 | 手机号/邮箱或验证码错误 | 401 |
| 图形验证码错误/过期 | 图形验证码错误或已过期 | 200（业务错误） |
| 登录失败锁定 | 登录失败次数过多，请 N 分钟后再试 | 401 |
| 发送验证码成功（登录/找回） | 如果该账号已绑定联系方式，验证码已发送，请注意查收 | 200 |
| 发送验证码成功（注册） | 验证码已发送，请注意查收 | 200 |
| 发送过于频繁 | 发送过于频繁，请 N 秒后再试 | 200（业务错误） |
| 注册重复 | 登录名已被占用 / 该手机号已被注册 / 该邮箱已被注册 | 200（业务错误） |
| 找回密码验证码错误 | 验证码错误或已过期（不区分账号是否存在） | 200（业务错误） |
| 未登录 / 令牌过期 | 未登录或登录已过期 | 401 |
| 无权限 | 无权限访问 | 403 |

## 6. 授权（RBAC）

- 数据模型：`sys_user_role` → `sys_role_permission` → `sys_permission.perm_code`（19 个权限点，3 个角色）。
- 接口鉴权：`@PreAuthorize("hasAuthority('task:manage')")`，**只认权限码，不写死角色判断**。
- 每次请求：`JwtAuthenticationFilter` 解析 JWT → `RbacService.loadAuthority(userId)` 实时回查角色与权限码
  → 注入 `SecurityContext` 与 `UserContext`。管理员收回权限后，旧 JWT 在下一次请求即失效。
- 前端：路由守卫校验 `auth_token`；页面用 `/rbac/me` 返回的权限码控制菜单/按钮；401 自动清理会话并跳登录页。
- 角色权限数量：`STUDENT` 7 / `TEACHER` 10 / `ADMIN` 19。

## 7. 配置项（application.yml）

```yaml
auth:
  captcha:
    expire-minutes: 5
    expose-in-response: false        # 仅 dev=true
  code:
    expire-minutes: 5
    resend-seconds: 60
    max-verify-attempts: 5
    expose-in-response: false        # 仅 dev=true
    sms:
      provider: mock                 # mock | http
      http-url: ${SMS_HTTP_URL:}
      http-token: ${SMS_HTTP_TOKEN:}
    mail:
      provider: mock                 # mock | smtp
      from: ${MAIL_FROM:no-reply@ai-trial.local}
  login:
    max-failures: 5
    lock-minutes: 15
  cas:
    mode: mock                       # mock | real
    server-url: ${CAS_SERVER_URL:}
    service-url: ${CAS_SERVICE_URL:http://localhost:8080/api/v1/auth/cas/callback}
    frontend-callback-url: ${FRONTEND_URL:http://localhost:5173/sso-callback}
  seed:
    enabled: false                   # 仅 dev=true
```

真实邮件通道还需配置 `spring.mail.host/port/username/password`；真实短信通道把 `provider` 改为 `http`
并填写网关地址与令牌。

## 10. 已知限制与生产加固

1. 验证码、state、ticket、登录失败计数均为**进程内存储**，服务重启清零；多实例部署需替换为 Redis。
2. JWT 无状态，**重置密码不会使已签发的旧令牌立即失效**（最长 24 小时）。生产可增加
   `token_version` / `password_changed_at` 校验，或引入刷新令牌与黑名单。
3. 默认短信/邮件为 mock 通道，验证码会出现在后端日志；生产必须配置真实通道并关闭
   `auth.code.expose-in-response` 与 `auth.captcha.expose-in-response`。
4. 统一认证默认为模拟 CAS；真实对接需学校提供 CAS Server 地址、协议版本与回调白名单。
5. 手机号/邮箱当前明文存储（接口与日志已脱敏）；生产建议列级加密或至少数据库访问审计。
6. 建议生产启用 HTTPS、网关限流（按 IP/账号）、短信每日配额与告警。
